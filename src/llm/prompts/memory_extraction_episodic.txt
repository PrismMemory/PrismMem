# Input Parameters
- Participants: `{{PARTICIPANTS}}` — the speakers in this dialogue. Each event facet usually belongs to the speaker who experienced or narrated the event; attribute it with `user_id`.
- Dialogue content: `{{USER_INPUT}}`. Each line is one turn in the form `TIMESTAMP [chat_id] speaker: text`, ordered oldest to newest. The bracketed token is that turn's `chat_id`; use its TIMESTAMP as the `mentionTime` for content drawn from it.
 
<MemoryTaxonomy>
Three facet types, contrasted.
</MemoryTaxonomy>
 
<ExtractionRules>
**Mandatory evidence-first processing order**
 
For every candidate event, follow this order before emitting JSON:
 
1. Identify the exact original utterance(s) that state the event and its concrete details.
2. Decide whether the event is eligible for an event facet from those utterances alone.
3. Choose `eventTypeL1` and `eventTypeL2` from the original utterance evidence only. While
   classifying, ignore any generated `content`, `context`, `tags`, or broad conversation/task label.
4. Write `content` as a source-preserving third-person rendering of the evidence.
5. Generate `context` and `tags` only after the evidence, taxonomy, and content are fixed.
 
**Mandatory source evidence**
 
- Every emitted event-facet record must contain a non-empty `sourceEvidence` list.
- Each item must be `{"chatId": <exact source chat_id or null>, "quote": <exact quote>}`. Copy the
  chat_id exactly as it appears in the bracketed token of the source line (e.g. `D1:2`); use `null`
  only when the line carries no bracketed id — never invent an id.
- `quote` must be a verbatim, contiguous span copied from the original utterance. Do not translate,
  paraphrase, summarize, correct, normalize, or add text inside a quote. Quote the utterance text
  only — never the `TIMESTAMP [chat_id] speaker:` prefix.
- Use the smallest sufficient quote that preserves the answer-bearing detail. For a record that
  aggregates multiple utterances, include every supporting quote as a separate item.
- Every factual detail in `content` and every taxonomy decision must be supported by
  `sourceEvidence`. If no exact supporting quote exists, do not emit the memory.
 
**Source-preserving content contract**
 
- Preserve every answer-bearing proper name, relationship, product/model, number, currency,
  quantity, unit, duration, frequency, time expression, location, participant, negation,
  uncertainty marker, condition, and name-to-attribute association in the original evidence.
- Grammatical third-person rewriting and merging compatible source statements are allowed;
  semantic generalization is forbidden. Never replace a specific detail with only a parent category
  or generic paraphrase. For example, `Vehicle Model A` must not become only `an EV`, and `around 250k`
  must not become only `a moderate budget`.
- The event taxonomy must remain fully justified when `content`, `context`, and `tags` are hidden.
- Before returning, compare each record with its supporting utterance(s). Repair any concrete
  detail that was removed, generalized, strengthened, weakened, or assigned to the wrong entity.
 
Extraction principles
1. **11-subtype priority**: extract as long as the described content **essentially** belongs to one of the 11 subtypes — whether one or several.
2. **Recall-value orientation**: the extracted memory should potentially help future understanding of a speaker's background, emotion, or needs.
5. **Format compliance**: output strictly per the JSON schema.
 
Field notes
 
1. content (third-person narrative)
- Include: event core, time (if any), place (if any), participants, key details.
- Preserve the original time expression in the narrative. When `eventTime` is uniquely resolved,
  it may follow in parentheses, e.g. "yesterday (2025-04-04)".
- Do not replace an unresolved or fuzzy original expression with a guessed date.
 
2. Time fields
Extract exactly these four temporal fields:
 
- `originalTimeExpression`: the event-time wording copied verbatim from the source, or `null` when
  the event has no explicit time expression.
- `mentionTime`: the exact timestamp of the source message that states the event. This is the
  dialogue time, not automatically the event time.
- `eventTime`: the normalized event time at the highest precision explicitly stated or uniquely
  resolvable from `mentionTime`. Use `YYYY`, `YYYY-MM`, `YYYY-MM-DD`, or `YYYY-MM-DD HH:mm:ss`
  according to the supported precision. Otherwise use `null`.
- `timePrecision`: `"year"`, `"month"`, `"day"`, or `"time"` to match `eventTime`; use `null` when
  `eventTime` is `null`.
 
Resolve a relative expression ("yesterday", "last Wednesday") only when it maps to one unique event
time at the claimed precision from `mentionTime`. A range or fuzzy expression such as "last week",
"as a child", or "once" is not one unique date: preserve it in `originalTimeExpression`, but set
`eventTime` and `timePrecision` to `null`.
 
Never zero-fill or guess an unstated year, month, day, or clock time. In particular, do not turn a
day-precision date into midnight and do not invent a weekday inside a week.
 
3. location
Explicit locations must be extracted, largest-to-smallest (e.g. "District A, City A, Region A — Science Park A"). Fuzzy locations may keep the original word; no location -> `null`.
 
4. participants
```json
[
  {
    "roleInEvent": "subject or involved",
    "entity": {
      "name": "entity name",
      "type": "entity type",
      "confidence": 1.0
    }
  }
]
```
 
5. Event classification (eventTypeL1 / L2)
Must strictly pick a level-1 and level-2 tag from the presets below. Make this choice by rereading
the original supporting utterance(s), never by classifying the generated `content`, `context`, or
`tags`:
- **Core Life Event** (`eventTypeL1: "Core Life Event"`): `eventTypeL2` in "Education & Growth" | "Skill Acquisition" | "Career" | "Family & Relationships" | "Life Transition".
- **Personal Experience** (`eventTypeL1: "Personal Experience"`): `eventTypeL2` in "Health & Medical" | "Consumption & Finance" | "Travel & Commute" | "Social & Entertainment" | "Emotion & Psychology".
- **Goals & Planning** (`eventTypeL1: "Goals & Planning"`): `eventTypeL2` in "Goal Setting" | "Plan Making" | "Intention Expression".
</ExtractionRules>
